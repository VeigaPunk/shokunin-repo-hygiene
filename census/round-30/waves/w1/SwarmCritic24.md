## Findings
1. **The target is reachable without executing any capability row.** `tools/souji-capability-agreement.py:178` checks only `first_path(cargv) != first_path(argv)`, i.e. one path-like token, so `cmd=python3 -c pass <row-script>` is accepted; `rc` and `observed` are then taken from the wrapper, and the row prints `CORRECTED` with the wrapper's `rc=0 observed=NONE`. Score: Finding/Evidence 2. Location: counter:129 (regex), 171 (match), 178; prereg line 5 keeps only "`cmd=` must keep the row's script path". Smallest safe correction: when `cmd=` is present require `shlex.split(cmd) == argv` exactly (and forbid `-c`/`--help` substitutions as a consequence).
2. **`mismatches=0` records annotation, not agreement.** The record-only state meets the exact target while all 13 stated literals still differ from their commands' output and R16's capability still exits 2. The prereg is explicit that "A correction records the observed state; it never edits a stated literal in place", so the SCORECARD cells (e.g. `SCORECARD.md:158` "`python3 tools/souji-landing-gate.py --selftest` 18/18") are unchanged at target. As worded ("these statements agree with what the committed commands print") the claim is false at target; what the instrument establishes is "no undocumented disagreement". Impacted axis: calibration.
3. **Base 13 overstates factual disagreement.** Honest split from `c1-before.txt`: notation-only 7 (R03, R06, R07, R08, R09, R10, R11 — e.g. stated `29/0` versus observed `SUMMARY total=29 failed=0`; the stated numbers equal the printed numbers); count disagreements 4 (R04 `5/5` vs `ids=7/7`; R05 `18/18` vs `pass=65`; R14 `9/9` vs `15/15`; R15 `8/8` vs `cases=12`); unobservable 1 (R18: command with no args prints a usage banner, `rc=0`, the capability never runs); broken command 1 (R16, `rc=2`). Factual defect count is 6, not 13; 7 of the 13 "mismatches" are notation and are what the correction trailer then footnotes.
4. **`KINDS` is wrong on two rows.** `tools/souji-capability-agreement.py:191-192` uses `it = iter(nums_o)` then `all(n in it for n in nums_s)`, so a repeated digit in `N/N` is consumed and R03/R06 are labelled `value` (counter says `value=7 shape=5`; containment gives `shape=7 value=5`). The field is diagnostic, but any report citing it mis-states the honesty split. One-line fix: `all(n in nums_o for n in nums_s)`.
5. **A correction is accepted while the capability is broken.** By design (prereg: "a row whose command now fails is corrected with its failing rc and reported as an operability limit, not repaired under C1"), R16 reaches `CORRECTED` with `rc=2` (Evidence 3). The SUMMARY has no field that distinguishes this from a corrected agreement, and in the bypass case (Finding 1) the printed row masks the real `rc=2` as `rc=0`. Honest only if the C1 report states that 13/13 cells remain stale and R16 remains broken; the target string cannot carry that.
6. **Normalization blind spots (both demonstrated).** `summary_line` (counter:77-80) returns the last digit-bearing line: a trailing noisy line such as `elapsed 0.42s files=12` hides an agreeing summary → false MISMATCH; a usage/help banner is a digit-bearing line (R18's live observed value), so a row whose command never runs can be "corrected" to green. The match at counter:171 is `stated in s` with no digit boundaries, so stated `8/8` matches `SUMMARY total=18/80 failed=0` → false MATCH. Smallest fixes: digit-boundary match (`(?<!\d)…(?!\d)`), and refuse `CORRECTED` when the observed line is a usage/help banner.
7. **The enumeration rule biases the claim.** `census/round-30/c1-rows.tsv:3` keys on an evidence cell "whose evidence cell names a runnable" command, excluding every count-bearing row without one. Excluded counts are not uniformly consistent: `SCORECARD.md:168` states "r20-audit-contract78/0 (base11)" while the committed fixture prints `total=66 pass=66`; `SCORECARD.md:164` states "(selftest 61/0, pointer fixture 11/0, r16 fixture 15/0)" — the same landing-gate selftest that `SCORECARD.md:158` states as `18/18` (enumerated as R05) and that the tool prints as `pass=65`, so one and the same stale count is counted on line 158 and excluded on line 164. The 18-row set therefore understates lane disagreement by at least one and keys on syntax, not on whether a count is stated.
