## Findings

1. DEFECT-NOT-FATAL — the `round-` cut rule hides real mistaken pointers. tools/souji-landing-gate.py:879 skips any token where `part.rstrip("/").endswith("round-")`. Counter-example (probe world `cutmistake`): a lesson line "see census/round- for the wave receipt" (a hand-written pointer missing its number) yields rc=0 with no finding at C2, while the base gate prints `LG-DANGLING-PTR census/round-`. The rule is required for tokenizer cuts (`"census/round-"+rd+"` — the token ends at the closing quote), but it cannot distinguish a cut from a truncated citation, and a skipped token leaves no exemption row and no counter trace. Latent: no live instance at tip (no scanned-source token ends in `round-`; no tree path component `round-` exists at tip, count 0), so no frozen target is affected today.
2. DEFECT-NOT-FATAL — TEMPLATE_POINTER_RE misses `%d`. tools/souji-landing-gate.py:156 is `TEMPLATE_POINTER_RE = re.compile(r"%s|<[Nn]>|\{N\}")`, but the diff's stated intent is that "a token that carries a template placeholder … is not a pointer", and the preregistration named the class as "template tokens (`round-%s`, `round-<N>`)". Counter-example (probe world `pcts`): a lesson citing `` `census/round-%d/waves/` `` gets `LG-DANGLING-PTR census/round-%d/waves/` at C2 (rc=1) — exactly the Python-style template shape the gate's own source uses (`round-%d` appears throughout the gate). The committed fixture's D4 covers only `%s`, `<N>`, `{N}`. Latent: no `round-%d` citation exists in gate-scanned sources at tip.
3. DEFECT-NOT-FATAL — wave-first discovery has no divergence finding. tools/souji-landing-gate.py:476-491: reports come from `.ufo/waves/round-N/` when it holds any `.md`, else from `census/round-N/waves/`; the comment says "When both are committed the wave dir alone is read, so no report is ever counted twice." Counter-example (probe world `shadow`): wave dir force-added with one clean report, capture holding that report plus `w2/Hidden.md` carrying `STATUS: FAIL - hidden uncarried failure.` → rc=0, checked_reports=1, no LG-SEAT-UNCARRIED; the capture-only failing report is silently unverified. Base behaves identically (reports=1), so this is not a regression, but C2 makes the capture authoritative evidence while leaving set divergence unflagged. Mitigated at the r29 runtime by amendment A1's BIND — "checked_reports from the SUMMARY line == committed .md count under census/round-29/waves == 86" — run on a private clone where the gitignored wave dir is absent; reachable only if a lane force-adds a partial wave dir.
4. DEFECT-NOT-FATAL (doc) — renamed `.captured` names still dangle, and the mapping's comment overstates. tools/souji-landing-gate.py:910 claims the capture "keeps the same relative names, so the same suffix is where the bytes were committed", but tools/souji-wave-evidence-capture.sh stores rule files `stored as "<same name>.captured" and recorded in renames.tsv` and ignores dest-ignored paths (`not copied; recorded in excluded.tsv with the sha256 of the source bytes and reason "ignored"`). Counter-examples (probe worlds `renamed`, `excluded`): a pointer to `.ufo/waves/round-30/.gitignore` still yields `LG-DANGLING-PTR` at C2 even though the world's capture holds the bytes as `.gitignore.captured` with a renames.tsv row; a pointer to an excluded.tsv-recorded path also dangles. For excluded paths dangling is honest — the gate verifies committed bytes only, and the exemption rail remains available; for renamed names the bytes exist under a recorded different name and the gate does not consult renames.tsv. Latent: r29/r30 captures have no renames.tsv/excluded.tsv rows and no scanned source cites a renamed wave path (grep count 0 at tip).
