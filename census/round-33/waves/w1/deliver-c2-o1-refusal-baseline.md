## Notes for the L1

1. The two `fleet-*` rows are the Q74 flip rows: at base the tool accepts a root inside a git work tree (rc 0, reusable). The candidate must refuse both while every `keep` row stays identical in rc and finding-id set.
2. The `.config` protection rule is anchored to `$HOME` (and each passwd home), not to the path string alone: a `.config` directory outside a protected home is not protected (observed: the alias fixture first returned rc 0 until it was re-pointed at a synthetic `$HOME/.config`, then rc 2 `record-protected`). The alias row therefore pins `HOME` to the synthetic sibling home; do not "simplify" it to a scratch-rooted `.config` or the case silently stops testing the guard.
3. `--selftest` was NOT used as the baseline runner: it hardcodes its fixture root (`tempfile.mkdtemp(prefix="souji-r14-cache-selftest.", dir="/var/tmp")`, tools/souji-evidence-cache.py:1295 at 2d9bca5) and would have written outside this seat's scratch bound. That hardcoded `/var/tmp` is exactly the O1 defect the repair moves to `TMPDIR`; this per-case table is the refusal baseline the repaired `--selftest` must keep matching.
4. Detail strings embed `<S>` paths and content digests; with the recipes above both are reproducible, so the L1 can compare full finding lines, not just ids.
