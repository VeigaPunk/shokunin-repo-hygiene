## C2 — operability 8: K4's status arm reads NUL records, and the writer delegation is named and its failure legible

Stated wording:
  In tools/souji-record-agreement.py, key K4 (uncommitted round work) has three new properties. (a) Its status read
  is `git status --porcelain -z`, so a path carrying a newline is parsed raw instead of in git's C-quoted spelling,
  and the record cell is C-escaped so one K4 record stays one physical line (the -z form's second NUL field of a
  rename is skipped; the rename record itself already reaches the key). (b) The tool prints one header line
  `# writer path=… sha256=…` naming the receipt-writer bytes it delegates its byte-truth and index-flag checks to, so
  a K4 verdict is bound to the delegation it used instead of leaving a reader to guess which writer sat beside the
  tool. (c) When the delegated writer produces no verdict, the K4 detail carries the writer's LAST non-empty stderr
  line — where an exception names itself — instead of the first 200 characters, which can end inside the traceback
  frame list. The frozen 12-row counter census/round-87/c2-k4-counter.py reports `SUMMARY rows=12 mismatches=0
  errors=0`, EXIT 0, on the filed tool bytes, while the do-nothing control — the same counter on the lane base's tool
