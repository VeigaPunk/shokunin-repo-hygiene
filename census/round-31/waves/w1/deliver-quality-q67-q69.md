## Dependencies and limits (integration must read these)

1. **Forward paths in Q68 and Q69's test cells and in three Block B rows.** At `1b81136` these do not
   exist: `tests/fixtures/r31-landing-gate-precision.py`, `tests/fixtures/r31-jj-object-clock.sh`,
   `census/round-31/records/jj-object-clock-run.txt`, `corpus/knowledge/jj-dropped-keep-object-lifetime.md`
   and `corpus/lessons/round-31.md`. Q65 forbids a landed row citing an uncommitted path, so Block A and
   Block B land in a commit at or after the C2, C3 and lesson landings — or the cells are trimmed to what is
   committed at that commit. Verified absent by `tests/fixtures/r31-*` glob and by a per-path existence probe.
2. **Q67's `record:` binding is a date, not a re-run.** The frozen target accepts a record binding whose
   integer multiset equals the base literal's. Such a binding shows the literal was the row's own round
   measurement; it cannot show the command still prints it. The criterion states this so a record-bound cell
   is never read as current evidence. Only `run:` bindings re-execute.
3. **The gate's carry token is looser than the frozen wording.** `tools/souji-landing-gate.py:111` accepts
   `resolved@` plus 7 or more hex characters; the preregistration requires `resolved@<full40>`. Q69 therefore
   adds its own full-40 check; the gate alone would pass a 7-hex token. This is a disclosed limit, not an
   amendment, and it is stricter-only.
4. **Q68's multi-section clause interacts with rounds 15, 19, 23, 24 and 25.** The preregistration routes
   their mid-file carry sections as residual "unless C2 lands first"; C2 is a claim that lands, so after it
   lands those rounds' uncarried lines are visible to the same gate. Q69 states the consequence rather than
   pre-committing those rounds as clean.
5. **No tool version claim.** This seat installed, upgraded and removed nothing; no package transaction ran, so
   there is no tool/version/channel row to record.
