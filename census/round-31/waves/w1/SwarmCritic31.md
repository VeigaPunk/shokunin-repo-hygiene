## Findings

1. **C1 run branch accepts a literal that is not the cell literal.** `tools/souji-capability-cells.py:214` tests only `len(ints(lit)) < 2` for a superseding row; `:237` then requires `at_bounds(lit, S)`; only the record branch (`:249`) enforces numeric equality: "the literal's integers, as a multiset, equal the base literal's integers" (docstring, `tools/souji-capability-cells.py:30`). Reproduced by Evidence 2. The frozen claim is "every enumerated cell literal is bound to an observable that shows it" (`preregistration.txt`, C1 paragraph), so a MATCH on `pass=65 fail=0` for cell `18/18` is a false calibration statement produced by a green counter. Impacted axis: **calibration** (the claim's own axis). Smallest safe correction: apply `sorted(ints(lit)) != sorted(ints(lit0))` in the run branch as well (stricter-only; the record branch already does exactly this).

2. **C1 record branch accepts a non-count literal.** `tools/souji-capability-cells.py:249` checks the integer multiset only; there is no count-shape test, so `15-config": LANE / "tests/fixtures/r15` (two 15s, no other digits) binds a `15/15` cell (Evidence 3). Impacted axis: **calibration**. Smallest safe correction: require the row literal to match a count form (`\d+/\d+` or `cases=\d+ pass=\d+`) in both branches; all seven literals that legitimately match at base (L01,L02,L30,L31,L36,L38,L40) already satisfy it.

3. **C1's frozen target is therefore not reachable honestly for L06.** Cell `18/18` at `SCORECARD.md:158` has no permitted observable: no round-16 non-transcript record contains an {18,18} substring (Evidence 4), and neither command named on that line can print it (selftest last line `SELFTEST pass=65 fail=0`; r16 fixture `SUMMARY total=15 failed=0`). Every route to `mismatches=0` for L06 runs through finding 1 or finding 2. This is a preregistration reachability defect discovered **before** C1 data, so it must be ruled on now: the prereg allows no target change after data, and amendments are stricter-only. Consequence if unruled: wave 1's C1 executor will either miss the kill rule or land a row that does not bind the cell literal — a **calibration** harm on the very capability cell that describes C2's instrument (`landing-claim gate`, `SCORECARD.md:158`).
