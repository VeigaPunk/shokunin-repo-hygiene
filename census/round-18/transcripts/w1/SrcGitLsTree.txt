## What it teaches (measured on b576341)

- `ls-tree -r --name-only` = 2246 blob/symlink paths; trees are omitted without `-t` (`corpus/knowledge`: 0 hits bare, 1 with `-t`). So it is not an all-object existence set.
- `cat-file -e` is type-blind: `b576341:corpus/knowledge` (a directory) → rc 0; a missing path → rc **128** `fatal: path '…' does not exist in 'b576341'`; a path prefix is not existence (128).
- Contrast that makes the trap: `rev-parse --verify --quiet <rev>:<path>` uses rc **1** for absence. Reusing the existing `blob_at_path` `returncode == 1` idiom (`tools/souji-landing-gate.py:204`) on `cat-file -e` turns every dangling pointer into gate exit 2. Reusing `blob_at_path` itself for a directory instead crashes: rev-parse succeeds on the tree, `cat-file blob <tree-oid>` → 128 `bad file` → `EvalError` (`:192-211`, `:157-171`).
- Non-`-z` listing C-quotes unusual names: exactly 2 paths in this tree (both newline names); `-z` emits verbatim.
- `ls-tree` `<path>` args are patterns: `corpus/knowledge/*.md` → 0 lines though 8 exist under the prefix; `:(glob)` magic is rejected; args are cwd-relative (from `corpus/`, `-- SKILL.md` → 0) while `<rev>:<path>` is not (rc 0 from `corpus/`).
