## C2 — operability 8: the vault CLI's signal path freezes the descendant tree before terminating it, so a CLI that forks a setsid'd child on the signal leaves nothing behind

Stated wording:
  In tools/souji-vault-verify.sh, cli_kill_tree freezes the CLI's descendant tree before terminating it: every
  descendant discovered by a fork-free pass over /proc/<pid>/stat (ppid after the last `)` of comm, starttime field
  22 re-checked before the signal) is SIGSTOPped before any trappable signal reaches it — a stopped process can
  neither run a signal trap nor fork — a second map pass catches a child forked in the read->stop window, and the
  frozen set is then SIGKILLed. The frozen 22-row population census/round-84/c2-population.tsv (the r83 20 rows
  unchanged, same order, plus l1-late-setsid-pid under the default launch and l2-late-setsid-group under the
  job-control launch) reports `SUMMARY rows=22 mismatches=0 errors=0 orphans=0`, EXIT 0, with both late rows
  `survivors=0 tmpleft=0` inside the frozen 5 s settle, while the do-nothing control K-a
  (census/round-84/controls/c2-K-a-r83-tool.sh, byte-identical to the r83 tool, sha256
  72a405f2c634712fb0211afb79f0462bf052b0b7c5fb8b663988017d2f1a8a18) reports `mismatches=2` on exactly l1 and l2,
  one nonce-carrying survivor each, and EXIT 1 (receipt census/round-84/controls/c2-before-r83-tool.txt).

Axis: operability. What moves: the tool's own signal path. The r83 walk reads /proc once and then TERMs each
descendant; a CLI that traps TERM and forks a child from its trap ran that trap between the read and the signal, so
the child was a descendant neither the map nor timeout's process group ever covered — and a `setsid` in the trap
takes it out of the group as well, so the group TERM and the group KILL fallback cannot reach it either (r83 A8/F5
stated limit; the r83 wave's MutTool showed the starttime re-check and the kill order carry no row). Freezing before
signalling removes the trap from the path: the CLI is stopped before it can react. The repair costs one more
fork-free pass inside the same settle.

Counting command (one, both ends):
  after:  python3 -B census/round-84/c2-late-fork-counter.py --tool <candidate tool> --work <an empty dir outside /tmp>
          -> target SUMMARY rows=22 mismatches=0 errors=0 orphans=0 ; l1/l2 survivors=0 tmpleft=0 ; EXIT 0
  before: the same counter on census/round-84/controls/c2-K-a-r83-tool.sh
          -> census/round-84/controls/c2-before-r83-tool.txt: SUMMARY rows=22 mismatches=2 errors=0 orphans=2, EXIT=1

Frozen population: 22 rows; the r83 20 keep their ids, signals, deliveries, stubs, timeouts, expectations, launch
and children columns; l1/l2 use the `latefork` stub, which installs a TERM/INT/HUP trap, starts a `setsid`'d
`sleep 600` on the first signal and then busy-loops on a shell builtin (a foreground `sleep` would defer the trap
past the tool's 0.1 s KILL sweep, so the row would measure the stub). A signal row matches iff the tool exits within
SETTLE=5.0 s of the signal with status 128+signal, writes the `souji-vault-verify: SIG<name>` stderr line, no
nonce-carrying process is alive at the settle sweep and the row TMPDIR is empty.

Kill rule (frozen): the claim fails on any ROW match=no, any errors>0, or a SUMMARY differing from the sentence above. The tool is killed by a late row that leaves a survivor or exceeds the settle, a lost SIG line, a leftover private TMPDIR file, its own `--selftest` going red, r17 (tests/fixtures/r17-jj-receipts.sh) going red, probe D (census/round-81/probes/tmpdir-in-vault.py) going red, a second pass that forks a pgrep/ps per node, or a signal delivered to a pid outside the CLI's descendant set.

Stated limits (frozen): /proc is not an atomic snapshot, so a descendant forked in the read->STOP window of its own parent survives pass 1 and is only caught if pass 2 still sees it as a child (a child whose parent was already stopped stays one; a child that setsids AND whose parent died in that window does not); a descendant that had left the tree (setsid before the walk) is a root of its own and is not found at all, before or after; pidfd is not used (bash only); the STOP->KILL pair widens the pid-reuse window the r83 tool disclosed (a pid reused between the last read and the KILL, with the same starttime, would be signalled); the `latefork` stub forks on the first signal only, so a CLI that forks on every signal is not a row; the deep stub remains a flat fan-out; a stopped process holds its locks and files until the KILL sweep, which is microseconds later.
