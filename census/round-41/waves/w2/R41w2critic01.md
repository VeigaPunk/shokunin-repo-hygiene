## Verdict

**C2 predicate falsified in part; C2 target is not evidence of operability.** The predicate says the tool "reports the grammar and freeze findings documented in c2-counter.py". On the landed bytes it does not for in-grammar input:

1. Empty `Counter:`, `Population:`, `Control:` or `Base:` values pass clean (rc 0). The documented class `FIELD-EMPTY` exists and is applied only to `Target` and `Kill`.
2. A NUL byte in a Counter or Control path crashes with a `ValueError` traceback and exit 1. The documented exit contract is 2 for could-not-evaluate, and exit 1 means findings.
3. A legal repo path with a space is a false finding (`COUNTER-/POPULATION-/CONTROL-MISSING`).
4. The DISPATCH-BEFORE-FREEZE check is silently skipped whenever the `Round:` line is not `Round: <digits>` at column 0 with LF endings and no BOM. A pre-freeze dispatch file then yields rc 0. The docstring documents the class but not the `Round:` key that gates it.

The frozen target still reads 21/21. The landed tool and the wave-1 candidate reach the same score, so the counter does not discriminate these defects (see Frozen counter below). Do not admit C2 on the landed bytes as an operable freeze check. The smallest repair I tested (a seat-local candidate, advice only) clears 11 of the 23 landed false greens; its residual gaps are listed in "Residual gaps".
