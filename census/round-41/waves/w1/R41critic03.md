## Verdict

**The frozen C2 target can be met by a candidate that never reads a preregistration.** Two tricks reach `SUMMARY cases=21 pass=21 fail=0 control_clean=REJECTED control_findings=REJECTED real=ok retro=red` with exit 0. The C2 counter therefore cannot tell an operable freeze check from a lookup table. Under preregistration rule 3, a memorising candidate that is smaller than an honest one would be selected. The L1 must not land C2 on the target alone.

## Answers to the assignment

- **Real and retro legs.** Both only check a path-string argument and a count. `real` requires `SUMMARY claims=3 findings=0` for `census/round-41/preregistration.txt` (counter lines 298–300). `retro` requires rc 1 and ≥3 `FINDING` lines for `census/round-40/…` (lines 301–303). Neither reads the prereg's content. T2 and T4 satisfy both with constants. They catch T1 and T3 only because those candidates emit clean for the lane paths.
- **Stub controls.** `control_clean=REJECTED control_findings=REJECTED` in all eight scored runs (T1–T4, the probe, and the three opaque-name runs). The stubs are scored against the same case list and never see the candidate, so they are candidate-independent. They verify only that the cases reject two always-same stubs. They cannot catch a gamed candidate.
- **Author identity.** The wrapper commits the candidate with `GIT_AUTHOR_NAME=fixture` before scoring, so the lane-leg rev carries the fixture author too. `receipts/probe.log` records `"prereg": "census/round-41/preregistration.txt", "author_subject": "fixture|candidate"` and the round-40 retro leg with the same value. The author is therefore not a fixture-only signal under the wrapper. The subject `candidate` is.

## Limits (named, not edited)

1. Legs and cases do not force the tool to read its input. Real and retro accept constants; the 21 cases accept any tool whose output matches on fixture names or fixture bytes.
2. Fixture directory names leak the case (`cand-<case>`); T1 and T2 use this.
3. Fixture bytes are deterministic (fixed counter/population digests, fixed messages, fixed trees), so a table derived from one run passes every later run; T4 uses this.
4. Preregistration rule 3 (all-target first, then smaller bytes) favours a memorising candidate that is smaller than an honest tool.

Suggested repair for the L1 and round lesson (not applied): run the real leg over a mutated copy of the prereg created in scratch and require named classes; use opaque or per-run-nonce fixture names and bytes (fresh salts in messages, subjects and digests); add hidden seeds the candidate cannot see; and require the `FINDING` detail to match the fixture's field.
