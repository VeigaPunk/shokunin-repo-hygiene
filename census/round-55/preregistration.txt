## Named limits carried into v4 (disclosed, not fixed)
The zone stays frozen at 32 chars (a token wholly beyond it is still not an
annotation and still forces exit 2 when no other annotation exists on the
line); the SOURCES scan is line-based and exempts lines carrying a
path-like pointer (extension-bearing paths only — a timestamp no longer
exempts, but a pointer-shaped fake such as `x.md:1` still does); annotations
whose pair does not exceed the current count are historical notes the
instrument does not re-derive (and pair filings under such annotations are
not audited — the r54 reviewer AF3e wording); pair annotations in files
other than LOG.md and corpus/README.md are invisible to the instrument
(AF4c two-file scope); an orphaned pair filing whose annotation moved
produces no finding of its own (AF4e); the registry's append-only
monotonicity is assumed; CR-only line endings (no LF) are one line to this
counter; the HTML comment class stays the line-level `<!--`/`-->` grammar,
not full CommonMark HTML blocks (an indented `<!--` still opens a comment
region); at most one ZONE-TOKEN-STRADDLES-EDGE registers per line (AF2b);
the finding-id precedence inside one correction is INERT, then BOGUS, then
IN-FENCE (AF3a: a wrong-stale filing is never also evaluated for BOGUS);
only the FIRST unknown receipt key is reported; unknown `# KEY=VALUE` lines
in the CAPTURE header are still ignored (the routed items name the receipt
only); free-form comments without tabs are still accepted (NL-2: the rule
cannot read intent); ENTRIES remains the tool's own count; the receipt binds
capture-to-receipt consistency and bytes, not execution or the capture's
path; FLEET_HEAD remains format-checked, not resolved; a prefix-tolerant
lexed correction whose prefix places it inside a fence is IN-FENCE first
(BOGUS prints before IN-FENCE only because the per-correction check order is
INERT, BOGUS, hidden — F21's first finding is BOGUS-RECOMPUTED).
