4. Falsifier found — the arm omits `--proc /proc`, so N3 cannot pass reliably
================================================================================
The envelope unshares the PID namespace but keeps the host /proc (`--dev-bind / /`; no
`--proc /proc`). Namespace pids are therefore resolved against the host procfs:
  inside the arm, bash $$ = 2, `cat /proc/$$/comm` = kthreadd, /proc/1/comm = systemd,
  `readlink /proc/self` = host pid 1845908 (R7).
  With `--proc /proc` added: bash $$ = 2, `cat /proc/$$/comm` = bash,
  `readlink /proc/self` = 6 (R7).
  A namespace child pid 3 reads host pid 3's comm = pool_workqueue_release without
  `--proc`; the same child reads `sleep` with `--proc` (R7b).
Consequence in the staged tool: tools/souji-census.sh:1547-1556 proc_state() reads
/proc/<namespace-pid>/stat; :1599 and :1638/1678 use it to decide the worker is dead.
With host /proc, a colliding pid is a live kernel thread forever, so the loop runs to the
cap at :1614, REPO_TIMEOUT*10+50 ticks with REPO_TIMEOUT default 600 (:238) — about 605 s —
while the fixture kills each tool run after 90 s (tests/fixtures/r14-census-boundary.py:399,
run_tool timeout=90). The fixture then records exit=124 and the case FAILs; N3's witness
(12 CASE lines + exact SUMMARY) fails even though the pin and canary are intact.
Reproduced without any load excuse and with load recorded:
  - full 12-case arm, load 32.04→55.00 (R2): CASE R14C2-07 exit=124, total=12 failed=1;
  - full 12-case arm + read-only clone, load 51.46→58.66 (R3): CASE 07 exit=124;
  - 01..07, load 54.75→49.04 (R8a): CASE 07 exit=124;
  - 04,05,06,07 (R8b): CASE 07 exit=124;
  - 05,06,07, load 36.93→19.71 (R8c): CASE 06 exit=124 (git-symlink and commondir),
    CASE 07 PASS — the hang moves between invocations, consistent with pid collisions;
  - committed feasibility-final.txt at 60def78 already shows the same shape:
    `LEG N3 FAIL cases=12 pinned=True summary=False`.
With `--proc /proc` added to the same arm:
  - full 12 cases, no read-only clone, load 12.00→16.26 (R9): 12/12 PASS, total=12
    failed=0, exit 0, ~6 s;
  - full 12 cases + read-only clone, load 13.68→13.22 (R10): 12/12 PASS, 6.49 s;
  - regenerate-shaped argv (timeout 300, relative fixture), read-only clone (R11):
    12/12 PASS, exit 0.
So the counter's current envelope is the cause of the N3 (and plausibly W2/W3/J1) misses,
not the NAMESPACE hold and not host load alone. This is an implementation defect in the
frozen counter: adding "--proc /proc" is a counter repair, not a predicate/target/item
change; the L1 owns that decision. Until it is repaired, `SUMMARY legs=13 pass=13 fail=0`
is not reachable for N3.
