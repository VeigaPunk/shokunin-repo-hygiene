## Findings

1. C1 rows G01/G07 can change measured output if `tools/souji-census.sh` changes while their SKILL registry statements remain unchanged. G17a/G17b can also be affected by a behavior-changing `tools/souji-evidence-cache.py` change through the acceptance runner. G02/G03 can be affected by changes to the r14/r15 fixture inputs. Those shared dependencies are outside C2's frozen touch scope: preregistration §C2 says “C2 touches only: census/round-34/c2-*, tests/fixtures/r34-*.” So no *allowed* C2 edit should move these C1 readings; a dependency change would also violate G2 for tool/old-fixture edits (and G6 pins r14). The transitive items' declared cause-file sets do not include those shared dependencies, so they could not honestly restate such a cause under C1's frozen rule. This is a latent coupling, not a reproduced C1 result change.
2. No C2 leg reads SCORECARD.md/SKILL.md contents. G2/G5 only inspect their path names in diffs/commit file lists; thus a row-text restatement cannot change a C2 measurement. A C1 docs-only commit does affect those guards' path inputs, but is allowed by G2 and does not overlap G5's C2 set when committed separately.
3. **ATTACK — G5 is narrower than the frozen “per-commit disjointness of the C1 and C2 file sets” wording.** The freeze commit `2b59192` in the enumerated base..freeze range touches both C1's `c1-counter.py`/`c1-items.tsv` and C2's `c2-counter.py`/`c2-legs.tsv`; yet the G5 code's C1 set contains only SCORECARD.md/SKILL.md, so this reproduced mixed-namespace commit is not flagged. G5 therefore does not enforce disjointness of the complete C1/C2 sets as worded. Do not alter frozen guard/predicate; preserve this as a reported attack. The three planned integration commits can still honour the *implemented* G5 check by keeping C1 docs and C2 counter/list paths in distinct commits. The observed freeze commit itself demonstrates that the full-file-set guarantee is not established by G5.
