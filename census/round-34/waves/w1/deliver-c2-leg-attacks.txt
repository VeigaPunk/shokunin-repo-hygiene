C2 frozen-leg semantic attacks (SwarmCritic20)

Scope: static attack against frozen bytes at list-rev 2b0171e2071fdc9c16a69bed12b0d040e574d8c8. No counter target run or fixture execution claimed; scratch reproductions were not performed.

1. W1 creates-clause does not establish the named tool did work. Counter `census/round-34/c2-counter.py:155-179,199-203` traces the entire shell command and accepts any traced file-creating syscall under its temporary TMPDIR or vt bind, with count >= half the base count. A fake `tools/souji-evidence-cache.py` that prints the genuine selftest line and additionally creates one file beneath TMPDIR can meet the target predicate without implementing the tool behavior; a script can also create irrelevant files to inflate the count. The current J1 stub only echoes the line and therefore does not falsify this stronger counterexample. This is a fixable witness-scope weakness, not evidence the frozen counter has already passed it. Smallest correction: bind the witness to expected tool-specific outputs/effects, or explicitly narrow claim to sandbox process file-creation activity and add a junk mutant that prints the line and makes an irrelevant create.

2. W1/W3/W4 syscall witness has blind spots. `strace -e trace=%file` is applied to the command execution at `c2-counter.py:157-158`; it cannot witness preparatory writes performed before strace starts. The matcher at `:177` requires one of open/creat/mkdir/rename/link/symlink/mknod/truncate and flags O_CREAT/O_WRONLY/O_RDWR/mkdir/creat. It does not recognize a memfd_create syscall (not a pathname create), and does not reliably recognize O_TMPFILE: its openat line contains O_TMPFILE but may not contain any of the listed O_CREAT/O_WRONLY/O_RDWR tokens. Thus a genuinely work-producing tool whose only observed creation is memfd or O_TMPFILE can be rejected; alternatively pre-trace setup can be mistaken for no work. Smallest correction: extend the recognized syscall/flag forms and trace the whole command lifecycle, or state this narrower witness limitation and add corresponding positive/negative fixture cases.

3. N4 does not guarantee load stability. The leg records one load reading and retries once only if >48 or its pair disagrees (`c2-counter.py` anchor implementation, preregistration N4 clause). Two coincidentally equal flaky readings at low load satisfy the predicate; moreover load can change during the runs after the single sample. The frozen definition operationally tests equality, not stability. Smallest safe correction is stricter-only: collect load for each run and require an explicit acceptable load band / repeated independent pairs; otherwise preserve the claim as equality-only, not load-stable.

4. N3 proves pin equality at the revision, not that the run left those bytes untouched. `leg_witness` checks the blob at `rev` using `blob(...)` and `pinned` at `c2-counter.py:195-198`; G6 independently hashes the same committed blob at `:230-233`. Neither hashes the fixture immediately before and after the namespace run. The private bind protects real /var/tmp and canary checking protects the real canary, but a run could modify its checked-out fixture copy and still pass both committed-blob checks. Smallest correction: hash the checked-out fixture before and after the run, in addition to the committed pin and real-canary checks.

5. J1 is a narrow stub control and can be bypassed by a special-casing fixture. `r34-sandbox-junk.py:88-94` supplies literal echo/printf stub argv; it does not run a counter stub that inspects `/proc/self/cmdline`. A tool/counter implementation can identify the fixture's invocation or these exact argv strings and behave honestly only there, while retaining the vulnerable production behavior. This is not shown to occur in the frozen counter, but the fixture cannot rule it out. Smallest correction: add a behaviorally equivalent mutation that detects its invocation and ensure the counter's acceptance is not keyed to fixture identity, while retaining frozen J1.
