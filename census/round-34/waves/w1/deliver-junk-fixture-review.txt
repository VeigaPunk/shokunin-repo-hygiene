- The RESULTS record path is not necessarily the semantic reason under a weakened implementation: the expected clause is matched literally in the emitted MISMATCH detail. Frozen counter itself requires n>=1 (`c1-counter.py:114-120`) and additionally file existence/history/content consistency (`121-138`).

### Assumptions left open
- It gets `tip` from literal branch `master` (`fixture:81`) and assumes that ref exists and names the desired reviewed tip; no explicit revision argument or assertion that `master` equals the counter's intended `--rev` is present.
- `root` is inferred from the supplied counter path (`fixture:71-72`); it does not verify that the counter is the frozen file or that the clone root is the expected lane.
- Git helper commands inherit the caller environment and invoke `git` without disabling system config/hooks (`fixture:47-50`); scratch commits use `-am`, relying on the sole SCORECARD modification being tracked and no staged content (`97-98`).
- The counter is invoked by absolute path outside the probe clone (`102-104`), so the fixture tests that implementation rather than a counter blob from `--list-rev`; replacement/mutation of the supplied file can change the result. That is appropriate for this fixture's invocation contract but not proof of counter immutability.
- It only tests one probe item/cause and the three named parser/validation clauses, not arbitrary malformed rows or alternative weakened implementations that produce expected detail strings without validating behavior.

## C2: r34-sandbox-junk.py

### Stub design and assumptions
- `tests/fixtures/r34-sandbox-junk.py:76-94` uses real captured final lines for W1/W4 but hard-codes documented lines for W2/W3/N3; capture failure silently falls back (`81-87`). These are plausible strings, not verified base outputs in this invocation.
- The stub argv are shell `echo`/`printf` commands (`88-94`), and legs are rewritten only in a scratch clone (`98-113`); each W/N leg should be rejected by actual work attestation, not merely exit/output comparison.
- The fixture does not fail closed on every counter error shape: it extracts only reported `LEG` failure rows for the named five ids (`121-125`) and checks nonzero rc. It does not assert each leg was evaluated exactly once, that there are no duplicate/missing leg IDs beyond the set test, or that the failure reason is work-related. A counter could reject all legs for unrelated reasons (or fail early after printing failures) and satisfy the intended assertion.
- Counter invocation timeout is fixed at 900 seconds (`117-119`), equal to the inner counter default; outer fixture has no exception handling around `subprocess.run`, so a timeout aborts without its promised `cases=...` receipt (`117-120`).
- It resolves root from the counter path and master from the lane (`61-68`), without explicit frozen counter hash/ref validation. Its committed clone fixture is only a probe of the passed counter, not a tamper-proof attestation of counter bytes.
- `p.returncode == 0` is rejected; additionally the expression `"control" in text and "STUB-REJECTED" not in text` is weakly scoped because it does not require a control marker at all (`126-127`).
