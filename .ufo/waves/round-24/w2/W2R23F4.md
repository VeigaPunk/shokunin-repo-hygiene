## Findings
1. **Hole confirmed.** `tools/souji-record-agreement.py:121` ("matches = COUNTS_RE.findall(text)") and `:126` ("m = matches[-1]") parse the whole receipt. That includes the recorded stderr and anything after it, so the last counts-shaped line anywhere wins. `STDOUT_FENCE` (`:70`) is defined and never used.
2. **The docstring contradicts the code.** `:118` says "Only the header region before the `--- stdout ---` fence is a receipt's own claim". The comment at `:125` says the opposite: "the LAST count line is the measured one". Neither describes the stdout section, which is where `run` puts the measurement (`souji-receipt-run.py:242-245`).
3. **Two authorities disagree.** On one receipt, `souji-receipt-run.py:251` ("counts = COUNTS_RE.search(proc.stdout)") reports `mismatches=7`, and K1 reports 0. `verify` doesn't bind the body bytes. Its counts check at `:295` (`RECEIPT-COUNTS-ABSENT`) searches `_body`, which includes stderr, so M-c passes. This is the same fence-blind class in the round-24 C3 tool. It is not in C3's frozen cases, so it is a disclosed residual, not a counter change.
4. **Contradicted r23 records**, all in `corpus/lessons/round-23.md`:
