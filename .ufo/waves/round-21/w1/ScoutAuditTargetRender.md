A related observed order is `:N:raw`: `census/round-18/transcripts/w1/CriticC3Measure.txt:79`: `→ read(/home/vgpnk/Projects/shokunin/souji-shokunin/.ufo/waves/round-18/make-w1.py:57:raw) ⇒ ok · 155 lines`. No standalone `:raw` without a further range was present in these examples.
- **Comma-separated read ranges (one target, multiple selectors).** `census/round-18/transcripts/w1/CensusWatchdog.txt:30`: `→ read(/var/tmp/souji-r18-CensusWatchdog/lane-5efb/tools/souji-census.sh:278-310,1540-1565) ⇒ ok · 68 lines`. Further ranges appear on lines 38, 54, and 62. The comma list is selector syntax, not the semicolon-separated target list used by grep/glob.
- **Read selector plus URI colons.** Round-20 `census/round-20/transcripts/final/AuditCase01.txt:47` and `:52` show `→ read(artifact://36799:raw:2-2) ⇒ ok · 3 lines` and `→ read(artifact://36799:raw:3-4) ⇒ ok · 4 lines`. `census/round-18/transcripts/w1/BaseArmLeaks.txt:40` has `→ read(skill://godspeed) ⇒ ok · 18 lines`. `artifact://` and `skill://` are URI schemes (colon is part of the URI), distinct from a filesystem target's trailing read selector; the frozen C1 contract excludes URIs.
- **Grep form and ` @ ` delimiter.** `census/round-18/transcripts/w1/ScoutBashFixtureTimeouts.txt:46`: `→ grep(timeout|&\s*(#.*)?$|\bwait\b|setsid|set -m|\$!|disown|coproc|\bkill\b @ tests/fixtures/r12-maintenance-guard.sh) ⇒ error · 1 line — Path not found: tests/fixtures/r12-maintenance-guard.sh`. This is `grep(PATTERN @ PATH)`; the target begins after the separator, and is relative here.
- **Semicolon-separated grep targets.** `census/round-18/transcripts/w1/ScoutBashFixtureTimeouts.txt:41` has `→ grep(timeout @ tests/fixtures/r12-maintenance-guard.sh;tests/fixtures/r13-quarantine-bounds.sh;tests/fixtures/r13-repo-struc…) ⇒ error · 1 line — Path not found: tests/fixtures/r12-maintenance-guard.sh, tests/fixtures/r13-quarantine-bounds.sh, tests/fixtures/r13-re…`. This is a relative multi-target list; the final component is visibly truncated. Also `census/round-18/transcripts/w1/CriticC2Calibration.txt:48` shows an absolute multi-target grep whose first target is visible and second is truncated: `→ grep(gate-replays|jj-receipts|LG- @ /home/vgpnk/Projects/shokunin/souji-shokunin/SKILL.md;/home/vgpnk/Projects/shokunin/souj…) ⇒ ok · 101 lines`.
- **Glob wildcard and semicolon-separated targets.** `census/round-18/transcripts/w1/BaseArmLeaks.txt:58`: `→ glob(/var/tmp/*census*.sh) ⇒ ok · 8 lines`. Multi-target form: `census/round-18/transcripts/w1/GatePointers.txt:323`: `→ glob(/var/tmp/souji-r18-GatePointers/lane/SHONEN.md;/var/tmp/souji-r18-GatePointers/lane/corpus/lessons/round-18-verifier-sp…) ⇒ ok · 4 lines`. Another glob list is `census/round-18/transcripts/w1/ProcCensusFixture.txt:364`.
- **Truncation marker location matters.** In `ScoutBashFixtureTimeouts.txt:41`, the ellipsis is within the last semicolon-separated target after `@`; in `CriticC2Calibration.txt:48`, it is within the second target after the semicolon; in `BaseArmLeaks.txt:66`, the `grep` pattern is visible but its target ends `…/r15-cen…`. In `GatePointers.txt:323`, the first glob target is complete but the second ends `round-18-verifier-sp…`. Under the frozen rule, a path component whose target is truncated is not flagged; do not guess its hidden suffix. Judge any other complete components independently, and flag once per call only if a complete component flags. A trailing `…` in an error diagnostic is different: round-20 `census/round-20/transcripts/final/AuditCase04.txt:49` has a complete argument `artifact://36855:1-3`, followed by `⇒ error · 1 line — Artifact 36855 not found. Available: …`; that diagnostic truncation is not argument truncation.
- **Error status renderings.** Glob missing-path example: `census/round-18/transcripts/w1/BaseArmLeaks.txt:44`: `→ glob(/var/tmp/souji-r18-BaseArmLeaks) ⇒ error · 1 line — Path not found: /var/tmp/souji-r18-BaseArmLeaks`. Read missing-path example: `census/round-18/transcripts/w1/ConnJjInteraction.txt:52`: `→ read(/home/vgpnk/Projects/shokunin/souji-shokunin/tools/souji-proc-census.sh:raw:1+30) ⇒ error · 1 line — Path '…/souji-proc-census.sh' not found`. Grep multi-path failure is shown above at `ScoutBashFixtureTimeouts.txt:41`; grep malformed-path failure also appears at `census/round-18/transcripts/w1/ConnPlanDataWalk.txt:49`. Status shape is `⇒ error · <count> line(s) — <diagnostic>`; successful calls use `⇒ ok · <count> line(s)`. R20 artifact-not-found errors use the same status shape (`AuditCase04.txt:49-50`), with an `Available:` list in the diagnostic.
- **Paths containing literal ` @ ` or colon.** In the sampled calls, ` @ ` appears as grep's pattern/target separator; no target path containing a second literal ` @ ` was observed. Thus handling an embedded ` @ ` in a filename is not demonstrated by this sample and its escaping/disambiguation remains unobserved. Colons are observed in URI schemes (`skill://`, `artifact://`) and in read selector suffixes (`:1-20`, `:raw:520+160`, `:57:raw`, and comma lists after a colon). No ordinary filesystem basename containing a literal colon was observed. The parser must distinguish URI targets from selector syntax and remove only the trailing read selector specified by the contract.

## Findings / remaining gap

The samples establish the visible call envelopes, selector variants, grep's `PATTERN @ PATH` split, `;` target lists for grep and glob, truncation inside path components, and both successful and failing status suffixes. The principal unresolved input shape is an actual path containing literal ` @ `; none was observed, so this report does not assert how such a filename is escaped. Read/grep/glob results were inspected as transcript data only; no target code, tests, builds, or live `/proc` content were run. No tools were installed.
