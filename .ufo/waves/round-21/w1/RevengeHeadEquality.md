**Axis:** operability. **Disposition:** source-only reconstruction; no code changes or runtime checks.

## Reconstructed contract

At pinned base `544c8358039a07e8b45e6db72312da5c8d965275`, `census/round-20/run-acceptance.py` was deliberately a once-only, byte-bound acceptance of an already integrated revision: its docstring says to run only after the integrated revision is committed. `main()` first resolves `--root`, refuses unless it equals the hard-coded `LANE` (`/home/vgpnk/Projects/shokunin/souji-shokunin`), then resolves the full durable `--rev` and checks its selected input tree. It separately runs `git rev-parse HEAD` in that root and refuses unless `HEAD == --rev` (the literal refusal rationale is “for the clean cache demonstration”). The recorded receipt labels `head_equals_revision` and `current_inputs_equal_revision` separately. This is not evidence of a general clean-worktree check: the source binds the declared input set and HEAD, and does not run `git status`.

The HEAD equality also keeps the `clean-cache-demonstration` step’s own revision observation aligned with the acceptance argument. The fixed 18-step inventory invokes `census/round-14/cache-demonstration.py`; the result matcher requires both `measured_commit` and `harness_revision` to equal `--rev`. That demonstration obtains its revision by resolving the HEAD of the root derived from its own script path, and rechecks the same revision/input snapshot at completion. So a different `--rev` from the measured root’s HEAD would not be a valid clean-cache acceptance, even if the named revision’s selected files happened to match.

The root restriction is explicitly explained in the refusal text: it is “the lane path used by the bounded r16/r18 fixtures.” At the pinned base, both `tests/fixtures/r16-landing-gate.py` and `tests/fixtures/r18-landing-pointers.py` embed the absolute lane path. The r16 fixture checks that path is a Git worktree and uses it for its historical replay; r18 likewise uses its embedded lane for the historical replay. Running either fixture from a copied root would therefore combine the copied runner/tool with a replay against the original absolute lane. The root equality prevents that mixed-root result.

## Clone verdict and divergence

A clone checked out at `--rev` meets the **HEAD-equality** part (assuming the full revision is durably resolvable there and the measured inputs match). It does **not** meet the old runner’s complete contract: its resolved root is not the hard-coded lane path, so source predicts a refusal before the 18 checks and before output. Removing only that path check would still leave the pinned r16/r18 fixtures replaying the original lane, not the clone.

Thus the old code’s direct operational intent was to bind the acceptance to the canonical integrated lane and its lane-rooted fixtures, not to provide non-author clone replay. The semantic provenance invariant—run the exact committed revision and its byte-bound inputs—can be satisfied in a clone, but the old path contract cannot. Round-21’s frozen C2 oracle intentionally changes the operational surface: it accepts an arbitrary local source repository, privately clones it, checks out `--rev` detached, and runs all commands against that clone; it also requires the r16/r18 fixtures to derive their root from their own file location. Under that revised contract, a clean clone at `--rev` is the intended measured root, while the source repository itself need not have `HEAD == --rev`.
