## Divergence: name-only config ban and harm

At the round-15 baseline, `guard_git_config` lists only local config key names with `git config --file ... --no-includes --name-only --list`, lowercases that output, then refuses on wildcard matches (`tools/souji-census.sh:493-507`). It does not inspect values or distinguish active from inert settings. The refused families are `include`/`includeIf`, filter clean/smudge/process, `core.hooksPath`, `core.attributesFile`, `core.excludesFile`, `core.alternateRefsCommand`, `remote.*.promisor`, `extensions.partialClone`, and `extensions.worktreeConfig` (also documented in `CensusBoundary.md:102-111` and `round-14.md:92-100`). This is a value-blind operability regression from the `a31642d` source. Because `list_repos` invokes `guard_git_surface` while collecting the fleet and refusal exits 2 (`:938-967`), one affected repository aborts the entire census before the header/rows (`:973-995`); benign or mixed fleets are not merely missing that one row.

**Previously honored harmless configurations (candidates, not individually measured):** the old source allowed any repository-local Git config to reach Git, but its selftest did not exercise these config families. For R15, safe candidates include `remote.*.promisor=false`, `extensions.worktreeConfig=false`, unmatched or benign `includeIf`, and inactive filter declarations; these are `[INFERENCE]` from names-only matching and must be proven with paired fixtures, not presented as established behavior. `core.hooksPath` is a particularly narrow candidate: the current census command set uses metadata/status commands, and `status` already overrides hooksPath to `/dev/null` (`:706-716`), so a path value need not be treated as evidence of a hook execution. Similarly, local excludesFile/attributesFile are overridden for status at `:710-712`; their mere presence does not establish that the configured file is read by this census. Do not preserve an entry by blindly accepting its value: value/activation and any alternate call path matter. The wildcard matching itself can also overmatch key names (for example prefix/suffix text), since it applies shell globs to the complete lowercased key list rather than comparing parsed canonical keys.

**Danger paths to retain fail-closed treatment for unless guarded:** an include/includeIf can introduce additional config and out-of-repository reads; a configured include/attributes/excludes/worktree path can reach the protected namespace; activated filters and alternateRefsCommand can invoke commands; active promisor/partial-clone state can trigger lazy object fetches; enabled worktreeConfig exposes additional per-worktree config not covered by the main config check. These are risk classes inferred from the config roles and census call path, not observed runtime effects. `core.worktree` already uses a value-aware path boundary check, rejecting `~` indirection and guarding the resolved target (`:508-521`); preserve this behavior. Keep protections for `.git`, commondir, alternates, linked-worktree registrations, and environment/config injection in addition to the R14 root/compare boundary.
