# Findings

1. **HIGH — revision pin can certify bytes other than the bytes the runners read (symlink / missing-tree-entry gap).** `resolve_durable` only normalizes the supplied path and rejects absolute or leading-`..` paths, then relies on `git diff --quiet`; it does not require the commit tree entry to be a regular blob or reject symlinks in the worktree (`tools/souji-rev-pin.py:130-147`). A durable revision can contain `tools/souji-evidence-cache.py` as a symlink to `/var/tmp/attacker.py`; if the link text is unchanged, the diff compares the symlink entry, while the r14 consumer later reads the resolved target with `Path.read_bytes()` (`census/round-14/run-verification.py:56-57`). The r13 runner also executes measured paths directly (`census/round-13/run-verification.py:426-444`). A measured path absent from the selected commit but present only as an untracked worktree file is another bypass candidate: `git diff` is not an untracked-file inventory, and the helper never confirms the path exists in the revision tree. **Impact:** a stamped commit need not contain the code/data actually read or executed. **Smallest guard:** for each measured path, require a tree entry at the revision with regular-file mode (100644/100755), reject symlink components in the worktree with `lstat`, resolve under the canonical repo root, and compare the bytes actually consumed (or consume the verified blob/snapshot). Close the check/read race if concurrent worktree mutation is in scope.

2. **MEDIUM — Git pathspec magic bypasses lexical path validation.** `--` prevents option parsing, but does not make subsequent Git pathspecs literal. `os.path.normpath(":(exclude)tools/souji-evidence-cache.py")` passes the current checks; supplying both `tools/souji-evidence-cache.py` and `:(exclude)tools/souji-evidence-cache.py` makes the second pathspec exclude the first from `git diff` (`tools/souji-rev-pin.py:130-136`). The CLI accepts repeated `--path` values (`tools/souji-rev-pin.py:296-315`). **Impact:** a caller-supplied measured path list can suppress the very comparison it claims to make. Current r13/r14 runner lists are constants, so the demonstrated route is the helper API/CLI or a future caller that accepts untrusted paths, not an observed user-controlled runner argument. **Smallest guard:** invoke Git with `--literal-pathspecs` (or use literal pathspec encoding) and validate each path as nonempty normalized slash-separated relative components; also require tree membership as in finding 1.

3. **MEDIUM — untrusted lesson text can drive quadratic regex work in the carry parser.** The newly added `ELLIPSIS_RE`, `LIST_ITEM_RE`, and `THEMATIC_RE` have no obvious nested-quantifier exponential backtracking in their call path; `carry_entries` normalizes whitespace before `ELLIPSIS_RE` is applied. However `lesson_lines` runs `HTML_COMMENT_RE = r"<!--.*?-->"` with DOTALL over the complete lesson (`tools/souji-landing-gate.py:123-126,378-380`). A lesson consisting of `"<!--" * 50000` with no closing `-->` gives the lazy wildcard a long failed suffix search at each opener; this is a quadratic CPU-denial candidate. Carry matching also tries every source-line prefix against each candidate entry (`tools/souji-landing-gate.py:446-464`), yielding unbounded superlinear work for a many-line STATUS paragraph and a long nonmatching lesson entry. **Impact:** a crafted tracked report/lesson can stall the landing gate. **Smallest guard:** replace comment stripping with a one-pass scanner (or enforce a conservative byte/line bound before parsing); bound paragraph/entry sizes or scan the entry once for physical-line cut points instead of re-running a search for every prefix.

4. **LOW — Unicode case folding makes ASCII carry tokens confusable.** The case-insensitive patterns are Unicode-aware, not ASCII-only (`tools/souji-landing-gate.py:98,108,110-111`). For example, `reſolved@abcdef0` (U+017F long-s in place of `s`) matches the `resolved@...` arm of `CARRY_TOKEN_RE`; `admıtted: true` (U+0131 dotless-i) can match the admitted marker. This can make a visually similar but non-contract token qualify a carry or admitted state. Python's `re.IGNORECASE` here is not process-locale-driven, so changing `LC_ALL` does not fix this. **Smallest guard:** add `re.ASCII` to case-insensitive ASCII protocol patterns (or spell out ASCII case classes). The revision helper itself sets `LC_ALL=C`, and its lowercase `[0-9a-f]` hash check is deterministic; uppercase-but-otherwise-valid SHA input is refused rather than mis-resolved (`tools/souji-rev-pin.py:32,45-53,96-109`).

5. **MEDIUM — Git repository-selection environment is inherited by the helper.** `_env()` copies the caller's entire environment and only overrides a few keys; `_git` then uses that environment for every `git -C root` call (`tools/souji-rev-pin.py:45-59`). A caller can set `GIT_DIR=/var/tmp/decoy/.git` and `GIT_WORK_TREE=/var/tmp/decoy`; the r13 runner's own `git()` uses a filtered `ENV`, but the imported helper reads `os.environ` directly (`census/round-13/run-verification.py:53-65,108-120`). The helper can therefore test reachability/tree state in a different repository from the runner's root. **Impact:** revision identity/durability and measured-tree proof may refer to different repositories. **Smallest guard:** construct an allowlisted child environment, clearing repository-selection and config-injection `GIT_*` variables; explicitly pin `GIT_CONFIG_GLOBAL=/dev/null` and disable replacement objects as appropriate.

**Negative control:** revision-string shell/option injection is not evident in the inspected helper. Attack strings such as `--help`, `HEAD^{/message}`, `40-hex^!`, or `;touch /tmp/x` fail the 40-lowercase-hex check; commands are argv arrays, not shell strings, and revision arguments are passed as one argv after controlled Git options (`tools/souji-rev-pin.py:56-59,96-109`). `../outside` and absolute paths are also refused (`:130-135`). Consider `fullmatch` for clarity, but `.strip()` plus the current anchored ASCII pattern leaves no demonstrated newline/option bypass.
