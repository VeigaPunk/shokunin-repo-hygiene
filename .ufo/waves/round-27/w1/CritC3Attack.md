## Findings
1. **[BLOCKER] No executable end-to-end C3 evidence yet.** Only w1 draft files exist; the prescribed tool and fixture paths do not. The prereg freezes presence + fixture result + receipt, so a proposed check is not an operability improvement until installed, run, and receipted. Smallest correction: L1 installs both drafts at frozen paths, invokes the fixture and receipt verifier, and records exact output; no predicate change.
2. **[ATTACK] Four cases leave a meaningful gate blind spot; control is wired but narrow.** Draft fixture lines 145-178 exercise clean pass, remote mismatch, missing heading and dirty tree; control lines 181-205 correctly first establishes a dirty world is rejected by the real gate, then asserts an always-pass stub falsely green is detected. But no case asserts missing/empty report, missing prereg, duplicate SHONEN headings, or a report that has only a heading and no protocol-required substance. In fact `write_report` lines 80-89 emits two boxes and “Evidence: none.”; clean-pass can pass this protocol-invalid report. Thus selftest's four case count is non-vacuous, but does not prove report readiness. Frozen C3 only mandates four cases and one heading; do not expand/change its frozen test post-data. Smallest safe correction is strictness-only: report this as an attack; separately L1 can perform/record canonical protocol content checks without claiming C3 counter covers them.
3. **[ATTACK] Heading predicate can false-green duplicate/variant content.** Gate draft lines 96-102 uses `grep -c '^## SHONEN'` and passes count 1, accepting `## SHONEN extra` as the sole heading. It also doesn't require SHONEN box lines. `PROTOCOL.md:163-165` requires one line per box (quote: “under a `SHONEN` heading with one line per box”). A broken report can therefore pass this check. Smallest correction: require the exact heading and protocol box-line shape in a stricter companion/report validation; retain frozen exact predicate/counter and report the residual attack to L1.
4. **[ATTACK] Clean-tree semantics can pass on irrelevant workspace state and allowlist can mask debt.** Draft gate lines 104-129 only checks `git status --porcelain` (not ignored files); this can pass with ignored uncommitted debris. Optional `--allow` accepts arbitrary relative prefixes and suppresses those paths. It checks whole worktree rather than classifying lane-authored vs aggregator-owned, so strict rejection may also block on non-lane-owned dirt; conversely caller allowlisting a broad directory can conceal lane-authored leftovers. Smallest safe correction: use explicit, narrow allow paths only when justified, report their exact contents/owners, and keep ignored/untracked worktree limits explicit; do not claim comprehensive cleanliness.
5. **[ATTACK] Tip equality is a reachability/equivalence check, not proof of intended push target.** Draft lines 79-87 compares one local ref to first `ls-remote` line for same name. This does exercise an actual bare/remote endpoint in fixture design, but a wrong configured `origin` (or absent/incorrect branch selection that happens to match) can pass. `ls-remote` failure becomes empty and fails closed; parsing first matching ref is reasonable for one exact ref. Smallest safe correction: L1 must confirm `origin` is the intended remote/branch outside this predicate and name the verified remote in evidence.
6. **[PASS WITH SCOPE] Git operations are read-only in the gate draft.** The draft invokes `rev-parse`, `ls-remote`, and `status`; no add/commit/fetch/push/reset or lane file writes appear. The fixture does mutate isolated `/var/tmp` Git repos and cleans them by trap, as intended. However gate only unsets a subset of Git environment variables and does not set `GIT_OPTIONAL_LOCKS=0` or disable auto maintenance, so “only read-only git” is not a strong universal side-effect guarantee under arbitrary configuration. Smallest correction: limit claim to these commands/no explicit mutation, or guard optional locks/maintenance and test resulting environment if stronger guarantee is required.
7. **[TRADEOFF] Real but modest operability gain.** `make-spec-r27.py:74` shows these are explicit L1 pre-report checklist steps; a single command can replace repeated manual probes and named failures are useful. Yet it is not a report validator and does not address the attempt-1 handoff failure by itself: the fixture always supplies `--prereg` and tests only file presence; it cannot establish the L1 will read the handoff or create the report. R27 lesson draft `.ufo/waves/round-27/w1/round-27.md:51-58` claims handoff readiness fix. Smallest safe correction: describe C3 as repeatable preflight, not handoff orchestration or proof of substantive report validity.
