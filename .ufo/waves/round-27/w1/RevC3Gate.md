## Findings
1. **F1 (critical, FALSE GREEN, demonstrated) — tip check is redirectable via ambient git env config; the scrub list misses the config-injection variables.** L24-33 unset a fixed `GIT_*` list but not `GIT_CONFIG_COUNT` / `GIT_CONFIG_KEY_0` / `GIT_CONFIG_VALUE_0` (`grep -n 'GIT_CONFIG_COUNT'` → no match). Any ambient `url.<x>.insteadOf` or config-injection env therefore rewrites `origin` for L81's `ls-remote`. Repro (scratch lane whose real origin is 1 commit behind): honest run → `check-tip=FAIL ... rc=1`; same command plus `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=url.file:///var/tmp/.../fake.git.insteadOf GIT_CONFIG_VALUE_0=file://...origin.git` where fake.git is AT the lane tip → `check-tip=PASS check-report=PASS check-shonen=PASS check-clean=PASS ... rc=0`. rc=0 FALSE GREEN while the branch tip is not on origin. Guard: scrub all `GIT_*` env generically (e.g. `while read -r v; do unset "$v"; done < <(env | sed -n 's/^\(GIT_[A-Za-z0-9_]*\)=.*/\1/p')`) AND verify the matched line's second column equals `refs/heads/$branch` before comparing SHAs (defense in depth; refname wildcards are not realizable — `git check-ref-format 'refs/heads/mas*'` and `'refs/heads/ma ster'` both REJECTED, so first-line-vs-pattern is safe today only against exact refs).
2. **F2 (critical for the clean check, demonstrated) — ignored files are invisible, so uncommitted lane-authored leftovers can hide.** L106 `git -C "$lane" status --porcelain 2>/dev/null` shows `??` untracked but not `!!` ignored. Repro: scratch lane with committed `.gitignore` naming `leftover.txt`, `leftover.txt` present uncommitted → `check-clean=PASS` while a leftover file sits in the worktree. Prereg C3 says "no uncommitted lane-authored leftovers in the lane worktree" — an ignored leftover is one. Guard: `git -C "$lane" status --porcelain --ignored=matching` (or additionally `git -C "$lane" clean -nxd`) and treat `!!` paths outside `--allow` as FAIL; parse with `-z` (see F6).
3. **F3 (high, demonstrated) — shonen regex prefix-matches foreign headings.** L97 `grep -c '^## SHONEN'` counts `## SHONENJUMP` (any `## SHONEN<suffix>` with no separating space). Repro: report containing only `## SHONENJUMP` → `check-shonen=PASS`. Prereg requires "exactly one `^## SHONEN` heading" (preregistration.txt, claim C3). Guard: `grep -cE '^## SHONEN([[:space:]].*)?$'`.
4. **F4 (low, demonstrated) — `[ -s "$report" ]` (L90) passes for any nonempty object, including a directory.** Repro: `--report <nonempty-dir>` → `check-report=PASS` (overall rc=1 only because grep on a directory fails, so fail-closed today, but the check line lies to any consumer that reads per-check lines). Guard: use `-f`.
5. **F5 (medium, demonstrated) — the gate is not read-only against the lane.** `git status` opportunistically refreshes and rewrites `.git/index` when the stat cache is stale. Repro (scratch clone): md5 of `.git/index` before vs after `touch tracked.txt; git status --porcelain` → REWRITTEN (`72f5cf32...` → `61002f6d...`); with `GIT_OPTIONAL_LOCKS=0` → UNCHANGED. The script exports `LC_ALL=C` but not `GIT_OPTIONAL_LOCKS=0`. Against the real lane this dirties `.git/index` metadata. Guard: `export GIT_OPTIONAL_LOCKS=0` next to `export LC_ALL=C` (L34).
6. **F6 (low, fail-closed but worth fixing with F2) — porcelain parsing without `-z` mangles renames and quoted (non-ASCII/space) paths.** L106-122 slices `p=${line:3}` and matches the raw string; `R  old -> new` and `"corpus/\346..."` entries can never match `--allow` entries → false FAIL, not false PASS. Guard: `status --porcelain -z --ignored=matching` with NUL-split parsing.
7. **F7 (low) — `--allow ''` is silently tolerated** (L59 `allows+=("$2"); shift 2 ;;` accepts the empty string; never matches anything, so it is a no-op exemption today). Guard: usage_error (rc=2) on empty `--allow`/`--lane`/`--branch`/`--report` values. Also: `"${allows[@]}"` on an empty array (L117) requires bash ≥ 4.4 under `set -u` (fine on this host's bash 5.x; note for portability), and L81 `ls-remote` has no timeout — a stalled network hangs the gate (availability, not correctness).
