## Findings
1. **[medium — vacuity] Success line is hardcoded, not derived from executed cases.** `printf 'cases=4 pass=4 control=FALSE-GREEN-REJECTED\n'` (r27-pre-report-gate.sh:224) fires whenever `FAILED=0` (:223), and `FAILED` only accumulates from assertions that actually ran. Proof: scratch copy with the entire case-2 block deleted → rc 0, identical frozen line (cases 1/3/4 + control ran). Dropping the control block would vacuously print the same literal. The counter (`w1/c3-counter.sh` awk exact-line match `/^cases=4 pass=4 control=FALSE-GREEN-REJECTED$/`) accepts it, and the prereg kill rule ("any case failing or the false-green passing") would not fire either. Fix (harness-internal, stricter-only; healthy output byte-unchanged): count executed cases and passes as they run and emit the frozen line only when the computed counts are 4/4 (or emit the computed line, which equals the frozen line when healthy).
2. **[low — determinism] Byte-level stdout volatility via commit SHAs.** Case 2's `detail-tip: local=… remote=…` embeds wall-clock commit times (commits are not date-pinned); a rerun delayed 2 s differed only in those two SHAs while the verdict lines and frozen line stayed identical. The counter parses only the final line, so the frozen counter is unaffected. Fix: pin `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE` in `commit_push` (:96-100) for fully byte-stable output. Note: ExecFixtureC3Tests.md's "byte-identical across two runs" held only because both runs landed in the same second.
3. **[low — residue] Cleanup misses `$WORLD_ROOT/home`.** `HOME="$WORLD_ROOT/home"` (:52) is created by `mkdir -p` but `cleanup` (:58-61) removes only the five world dirs; `home/` (and WORLD_ROOT itself) persist after every run (observed). Fix: include `home` (or the whole WORLD_ROOT) in cleanup.
4. **[low — concurrency] Fixed WORLD_ROOT invites cross-run collisions.** Two concurrent harness instances (counter, MutC3Checks, reviewers) share `/var/tmp/souji-r27-ExecFixtureC3Tests` and each `mkworld` does `rm -rf` on the shared per-world paths (:67) → intermittent spurious failures. Lane fixture convention is `mktemp -d` under /var/tmp — "All scratch lives under `mktemp -d /var/tmp/...` and is removed by trap." (tests/fixtures/r13-quarantine-bounds.sh:42). Fix: `mktemp -d` under the frozen root as parent.
5. **[informational — coverage, frozen case set] Red paths for `report`, `prereg`, and SKIP are never exercised.** Every world carries a nonempty report and `run_gate` always passes `--prereg` (:102-109), so `check-report=FAIL`, `check-prereg=FAIL`, and the SKIP verdict have no case. Expanding the case set is a case-set change → L1 stricter-only amendment territory; reported, not implemented. Related: case 1 (:147-161) is the *only* enforcement point of the rc-0-on-green contract — under the exit-liar mutant, cases 2-4 and the control all passed (their want-rc is 1) and only case 1's rc assert rejected it — which raises F1's stakes (dropping case 1 would blind the exit contract too).
6. **[informational — cross-seat] Gate unsets `GIT_CONFIG_NOSYSTEM` that the harness exports.** The gate's scrub list includes `GIT_CONFIG_NOSYSTEM` (souji-pre-report-gate.sh:19-27), so inside the gate git would read `/etc/gitconfig`; absent on this host (verified), no effect here, but on hosts with a system gitconfig the fixture could behave differently. RevC3Gate's scope; recorded for the interaction.
7. **[informational — evidence integrity] Executor report predates the final harness bytes.** ExecFixtureC3Tests.md cites a 7899 B draft and proves the harness with a self-written reference gate; the current file is 8032 B (the `assert_case 1 clean-pass 0` rc assert and the `run_gate` rc-capture fix landed after), and the real-gate pairing was unproven until this review's run 1 (now green). Its claim "case 1 asserts all five checks PASS and rc 0" is true of the current file.
