## Attack log

**A1 — K4 is gameable by flag and by exemption breadth.** `--no-worktree` skips the key outright
(F6); a broad `uncommitted:` prefix (`uncommitted:tools/`) would exempt every tool, and a bare
`uncommitted:` row with an empty path is correctly dropped by the `if path:` guard. Required
mitigations, all cheap: the after receipt must carry the prereg's command verbatim (no
`--no-worktree`), and the only added exemption row must be the operator sweep (F8b). The prereg
permits exactly that row ("operator-owned paths only"), so no predicate edit is needed — I am
**not** proposing one.

**A2 — K4 is not a revision-bound predicate** (F7). A receipt that prints `--rev <tip>` beside a K4
result implies the revision determines it; it does not. Mitigation without touching the counter: the
after receipt must record `git status --porcelain` stdout beside the counts line, so a verifier can
re-derive the K4 half from the receipt rather than from a later tree state.

**A3 — the base control is not D1-pure.** Of the 17 control mismatches, 7 are D1's paths, 2 are K1/K2
pre-existing, 2 are K3 (D4), and **9 are this round's own artifacts** (`.ufo/waves/round-23/`, the
two untracked tools, `tools/__pycache__/`). The control therefore fires (M ≥ 1) partly for reasons
unrelated to D1. This does not weaken the D1 conclusion — E5 names the seven paths individually — but
the control receipt must be the **full** stdout, never the counts line alone, or the D1 signal is
lost inside it.

**A4 — robustness note, not triggered:** `k4()` parses `line[3:]`, so a porcelain rename entry
(`R  old -> new`) yields a path containing `" -> "`; the exemption prefix-match and the reported path
would both be wrong. No rename exists in the current tree.
