## Residual risk (accept; sizing notes, not defects)

1. The presence clause is nearly implied by `tally-disagree`: any surviving occurrence must already
   equal the receipt, so presence only forces at least one mention per class. Its independent power
   is real but narrow (proved by the round-22.md `refused` case, whose sole occurrence is line 355).
2. The predicate is shape-bound. `accepted: 9`, `7 Accepted`, `(9/9/9/9)` and `accepted 9` all pass
   (all four probed: `mismatches=0 EXIT= 0`). This is inside the prereg's letter (`<n> <class>`) and
   the tool docstring says so; it belongs in the named limits if a future round wants it closed.
3. K3 verifies agreement between two records and one receipt; it does not re-derive verdict classes
   from the slice bytes. The prereg declares "the VALUE is always derived from a receipt", so this
   is contract, not a gap — but C1's "self-assessment vs observed repo state" is only as strong as
   the receipt's own cells for K3.
