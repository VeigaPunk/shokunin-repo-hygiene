## Findings
1. **D3 survivor set before/after.** Of 19 clause mutants, 15 survive the 8-case fixture and 7 survive the 12-case fixture: m04, m13, m14, m15, m16, m17, m18. Cases 9–12 kill exactly the bare, empty-bare, subdir and partialClone-only clause mutants (m01, m02, m03, m09, m10) plus the stderr-handling mutants (m11, m12, m19). Case 10 is the only case in either fixture where git exits 0 but writes non-warning stderr, which is why it kills the stderr mutants.
2. **m04: the `remote.*.promisor` refusal is still unpinned.** In case 6, the clone refused in its first arm also carries a `.promisor` pack, and the third arm (`promisor_unset`) removes the remote flag. Case 12 sets only `extensions.partialClone`. So no case has a promisor remote without the other two triggers, and the pack scan (m05) masks this clause. Fixture witness shape: `remote.origin.promisor=true` on a plain repo, expecting rc 2 and "promisor remote".
3. **m13: the `invoked_from=linked` label is unpinned.** Case 4 asserts only counts, a witness and the manifest. Case 9 is the only place `census.invoked_from` is checked, and only for `bare`.
4. **r24 finding 8 does not hold for this tool blob.** r24 judged m07/fsmonitor "equivalent on every input tried" and said the `--git-dir=<common>` read masked it. With blob `182001db` at a6d2d15 and git 2.56.0, the repo's fsmonitor hook runs under the census's own `--git-dir=<common> fsck`; the worktree is inferred because core.bare is unset. So `-c core.fsmonitor=false` is a live guard against running a program the repo controls. Without it the tool runs the hook and then fails on the hook's stderr. If a hook's output keeps git quiet, the tool would run it silently. r24 tested a different tool blob (`a710dfa…`) with an unspecified hook script, so the two observations may both be correct for their inputs [INFERENCE]. Either way, a fixture case with a marker-writing `core.fsmonitor` and an assertion of `marker absent and rc 0` kills m18 here.
5. **m14, m16, m17, m15 are unchanged from r24 findings 4, 2, 7 and 3.** The fixture strips `GIT_*` from the tool's env. Case 2's lone blob makes `--dangling` and `--unreachable` agree. Case 5's alternates file has one valid line. The fixture's 120 s TIMEOUT is below the tool's 900 s, so no in-fixture hang case can tell a 900 s timeout apart from no timeout.
6. **Stub control holds.** The stub fails 4/8 and 8/12, giving `control=FALSE-GREEN-REJECTED`. The new cases add 4 more stub failures; case 9 fails because the stub never prints `census.invoked_from=bare`.
7. **The 12-case draft's disclosed limit is confirmed.** For cases 10–12 the docstring says manifest_changed is reported but not gated. Every mutant here showed `manifest_changed=0` on those cases, so leaving it ungated cost no kills in this set.
