## Can dependencies be complete?

A **repository-file closure** is statically enumerable for the listed checks. With a common root at `/home/vgpnk/Projects/shokunin`, the lane files and the external `scripts/sources-census.sh` can all be represented by relative paths; using the lane itself as root would not contain the external validator. Hash the relevant files as they existed for each run, including fixtures and data, not just the current six tools. For the Git baseline case, bind the exact BASE blob/materialized bytes. For the frozen case, include `expected.json` as well as the seven pins.

That is not by itself a **complete execution-dependency key** for this suite. The results also depend on tool binaries and versions (`python3`, Bash, Git with `repo structure --format=lines`, `rg`, `shellcheck`, `gawk`, coreutils/`timeout`, and optionally `localedef`/locale data), environment/PATH, UTC date, filesystem metadata/type/link/FIFO behavior, temp-filesystem state, and Git object/config state. The source-contract check additionally depends on the external root config and directory roster, and on `used-by` existence, not merely a static list of repository text files. The present result schema stores neither these identities nor the check's dependency digests. It is possible to make a useful complete file manifest; complete reuse across hosts requires also freezing or recording these non-file execution inputs, or refusing to reuse checks whose environment is not bound. **Current outputs cannot establish that completeness.**
