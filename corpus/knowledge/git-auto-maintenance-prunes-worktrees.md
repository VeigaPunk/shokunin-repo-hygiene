# Git auto-maintenance can prune worktree registrations without a souji receipt

## Claim (F1: Git housekeeping vs receipts)
A successful `git commit` can trigger worktree-prune as a side effect on Git 2.55.0:
1. `builtin/commit.c:1965@v2.55.0` calls `run_auto_maintenance(the_repository, quiet);`.
2. `run-command.c:1961-1967,1974-1982@v2.55.0` enables it by default and launches `git maintenance run --auto` (`:1980-1982`; auto-detach defaults to true when both `maintenance.autoDetach` and `gc.autoDetach` are unset, `git-maintenance.1.txt:533-539`). S001 § maintenance.auto says commands run `git maintenance run --auto` after normal work; “Defaults to true.” (`git-maintenance.1.txt:523-531`, installed 2.55.0).
3. With no `--schedule`, `builtin/gc.c:1974-1975@v2.55.0` selects `geometric_strategy` and `MAINTENANCE_TYPE_MANUAL`. The geometric worktree-prune task is `SCHEDULED | MANUAL`, `WEEKLY` (`gc.c:1916-1919@v2.55.0`); the manual type admits it at `:1989`, while the weekly schedule test is inside `if (opts->schedule)` (`:1992-1999`). Thus `--auto` does not wait for the weekly schedule. S010 says: “"git maintenance" starts using the "geometric" strategy by default.” (`Documentation/RelNotes/2.54.0.adoc:58@v2.55.0`).
4. `maybe_run_task` applies the `--auto` condition (`gc.c:1771-1773@v2.55.0`). Worktree-prune's condition starts with `limit = 1`, reads `maintenance.worktree-prune.auto`, and requests the task when at least that many registrations are prunable (`gc.c:394,399-420@v2.55.0`; default documented at `git-maintenance.1.txt:755-767`). The task runs `git worktree prune --expire <gc.worktreePruneExpire>` (`gc.c:379-388@v2.55.0`); default expiry is `3.months.ago` (`gc.c:162@v2.55.0`).
5. `worktree.c:954-956@v2.55.0`: an existing `locked` file skips pruning. For a valid admin entry whose gitdir target is absent, `:1001-1008` marks it pruneable if `index` cannot be statted or its `st_mtime <= expire` (normally 3 months ago). Separate malformed/missing admin-directory or gitdir-file cases return as prune candidates at `:949-953,958-993`; they are not protected by the missing-target index-age test. S003 says `git worktree lock` prevents the admin files from being pruned (`git-worktree.1.txt:58,167-168`, installed 2.55.0).
